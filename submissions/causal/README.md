# CausalProof community evidence registry

This directory is the content-addressed ledger for structural runtime causality
and the ScheduleProof drafts derived from it. CI independently recomputes the
entire structural trace → causal ledger → bounded schedule evidence chain.
Unsafe ScheduleProof results are welcome when the evidence is valid.

Admission means only that the submitted, content-free structural fields,
operator assertions, digests, and deterministic reports recompute. It does not
establish trace completeness, clock synchronization, production probability,
system safety, compliance, government endorsement, non-repudiation, or an
authorization to operate.

## Submit an experiment

1. Create a strict span-to-event manifest and run CausalProof locally:

   ```bash
   dspy-security-bench causal init \
     --trace-out causal-trace.json --manifest-out causal-manifest.json
   dspy-security-bench causal run causal-trace.json causal-manifest.json \
     --report-out causal-report.json \
     --scenario-out scheduleproof.json \
     --schedule-report-out scheduleproof-report.json
   ```

2. Build a self-contained public bundle. The builder strips names, attributes,
   events, status, resource, scope, prompts, arguments, results, and credentials;
   only structural identifiers, parent/link relationships, timestamps, and
   dropped-record counters remain.

   ```bash
   dspy-security-bench causal bundle causal-trace.json causal-manifest.json \
     --submitter @you \
     --runtime "your-runtime@version" \
     --source-repository https://github.com/owner/repo/tree/COMMIT \
     --known-gap "sampling policy omitted unsampled spans" \
     --out your-runtime.json
   dspy-security-bench causal verify-submission your-runtime.json
   ```

3. Inspect the generated bytes. Structural timestamps and identifiers are still
   metadata; use synthetic inputs or an owner-approved pseudonymization and time-
   bucketing policy when public disclosure could create risk.
4. Use a lowercase kebab-case filename, place it here, and open a pull request.
   Pin the source URL to the exact tested commit and disclose known gaps.

The fictional reference case demonstrates the format but is intentionally not a
community submission.
