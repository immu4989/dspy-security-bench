# v0.9.0 — ControlTwin policy-efficacy evidence

DSPy Security Bench now closes the loop from an observed prompt-injection
failure to a tested deterministic control.

## Highlights

- `dspy-security-bench impact control` runs the frozen ProcureBench protocol
  with policy off and policy on, using a fresh agent for every case and
  condition.
- Functional harm containment, safe mission recovery, clean mission utility,
  poisoned mission utility, and synthetic economic exposure remain separate
  measures—there is no blended score that can reward a deny-all policy.
- Every requested tool call receives a benchmark-owned policy-boundary event;
  rejected calls are paired with the absence of the live environment state
  transition.
- Reports embed both complete ImpactTwin conditions and the normalized policy,
  whose semantics are bound to a canonical SHA-256 digest. A separate digest
  identifies the complete evidence payload for provenance and reproduction.
- `impact control-verify` recomputes the digest and every aggregate offline.
- SARIF separates residual functional harm, mission recovery gaps, and
  clean-workflow regressions for GitHub code scanning.
- Independent CI gates cover controlled harms, clean-utility loss, and optional
  controlled attack resistance.
- Tool arguments remain redacted by default, with an explicit opt-in for
  environments where the evidence classification permits capture.
- The interactive dashboard includes a responsive policy-off/policy-on lab and
  pair-level containment/recovery view.

## Zero-cost demonstration

```bash
pip install dspy-security-bench==0.9.0
dspy-security-bench impact control-demo
```

The deterministic vulnerable reference moves from five harmful poisoned pairs
to zero and from $3.69M of synthetic scenario exposure to $0 while keeping clean
mission utility at 100%. Three attacked missions fully recover; two are labeled
contained/recovery-gap instead of being misrepresented as complete passes.

The reference agent and approval callback are scorer fixtures, not model
results. A single policy-off/on comparison is not a stable effect estimate for
a stochastic provider; repeat both conditions before making broader claims.

Read the [ControlTwin guide](../control-twin.md) for the evidence model,
approval callback contract, CI setup, research context, and limitations.
