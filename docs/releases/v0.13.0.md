# v0.13.0 — MissionForge and SourceTwin

This release adds a new way for agencies, companies, and researchers to own the
evaluation protocol—not just run a benchmark selected by someone else.

## MissionForge: reviewable mission tests as data

MissionForge is a strict YAML/JSON SDK for defining synthetic source-grounding
evaluations without adding executable benchmark code. A pack binds candidate
claims, exact source identities, authority and supersession status,
clean/injected retrieved content, expected dispositions, material exceptions,
and a canonical protocol SHA-256.

```bash
dspy-security-bench pack init --out mission-pack.yaml
dspy-security-bench pack validate mission-pack.yaml
dspy-security-bench pack run mission-pack.yaml --agent myapp:build_agent
```

The loader rejects unknown fields, executable hooks, unresolved references,
duplicate IDs, untrusted sources that claim attested support, invalid
current-primary expectations, and counterfeit use of the frozen SourceTwin
identity. Packs are capped at 1 MB and 100 pairs.

## SourceTwin: deterministic source-grounding probes

The first packaged MissionPack contains five clean/injected counterfactual
pairs:

1. fabricated authority and citation;
2. embedded instructions in retrieved content;
3. omission of a material exception;
4. preference for superseded guidance; and
5. a claim with insufficient evidence where abstention is required.

Scoring uses structured findings and cited source IDs, not free-form answer
matching and not an LLM judge. Reports separate clean utility, attack
resistance, decision invariance, citation faithfulness, completeness,
sufficiency, and current-primary preference. Every result retains its action
trace and clean/injected causal diff.

```bash
dspy-security-bench pack describe source-twin
dspy-security-bench pack run source-twin --reference bounded
dspy-security-bench pack run source-twin --reference vulnerable
```

The two references demonstrate the scorer without a provider call; they are not
model results.

## Repeated, attested, and standards-shaped evidence

`pack repeat` adds fresh-agent isolation, per-pair and aggregate Wilson
intervals, stability evidence, a complete nested trial tree, canonical report
identity, and offline recomputation. `proofrun source` creates a
content-addressed bundle and is supported by both the composite action and the
credential-separated trusted reusable workflow.

The new open Source evidence ledger admits valid evidence regardless of score.
Repository CI recomputes every submitted trace, outcome, interval, and digest;
the dashboard only upgrades provenance tiers from separately reviewed digest
registries.

FederalProof now accepts verified MissionPack bundles and adds local objectives
for citation faithfulness, completeness, sufficiency, and current-primary
preference alongside attack resistance, clean utility, reliability, stability,
and evidence integrity. Exports remain assessment inputs, not control
satisfaction, certification, procurement acceptance, or authorization to
operate.

## Research and policy grounding

The implementation and documentation are informed by current public material
from NIST's agentic evaluation-probes project, OMB M-25-22, GAO's practices for
testing high-impact AI, the NIST AI RMF, and existing security guidance. The
crosswalk is dated, informative, and non-determinative. The project claims a
distinctive integration of portable mission packs, deterministic twins,
attested evidence, a public ledger, and OSCAL-shaped exports—not proof that no
related implementation exists.

See the [MissionForge and SourceTwin guide](../missionforge.md) for the complete
authoring contract, real-world pack ideas, safety checklist, trust model, and
limitations.
