# v0.6.0 — RepeatTwin: uncertainty you can inspect

v0.6.0 turns DSPy Security Bench from a model leaderboard into a broader
agent-security evaluation and contribution platform.

## Headline capability

RepeatTwin runs all five clean/poisoned ProcureBench pairs repeatedly and keeps
every raw trial. It reports pair-specific and fixed-suite Wilson score
intervals, outcome instability, trace equivalence, runtime errors, elapsed time,
and provider-reported token/cost coverage.

```bash
pip install --upgrade dspy-security-bench==0.6.0

dspy-security-bench impact repeat \
  --agent your_package.security:build_agent \
  --trials 10 \
  --min-lower-bound 0.80 \
  --json repeattwin.json
```

CLI runs create a fresh agent for every case to prevent cross-twin memory
contamination. Reports created by library callers that reuse one object are
marked and cannot enter the community result directory.

## Fork-to-contribute results

`impact submit-result` creates a content-addressed bundle containing every raw
trial. `impact verify` recomputes statistics, pair-level intervals, outcome
classes, usage totals, protocol identity, and canonical SHA-256 digests without
calling a model. Pull-request CI runs the same verification.

Hashes establish internal integrity—not signer identity. Provider, runtime, and
submitter metadata remain explicitly self-attested.

## Compatibility and evidence contracts

- `AgentResult.usage` is optional; existing agents remain compatible.
- ImpactTwin JSON advances to schema v3 to carry usage coverage.
- `impact explain` continues to read schema-v2 BoundaryDiff reports.
- RepeatTwin and community bundles use separately versioned schemas.
- Reference fixtures demonstrate the scorer and are never accepted as model results.

All economic values remain synthetic scenario exposure—not predicted loss.
Passing is not a safety, acquisition, legal, or compliance certification.
