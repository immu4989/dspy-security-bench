# v0.19.0 — Containment evidence for autonomous-agent collectives

v0.19.0 introduces CollectiveGuard, a vendor-neutral structural protocol for
testing whether autonomous agent runs stayed isolated, respected network and
credential boundaries, treated peer messages as untrusted, stopped safely, and
reached accountable responders in time.

The release was developed from the control and response lessons in OpenAI's
[Hugging Face incident overview](https://openai.com/index/hugging-face-incident-and-the-road-ahead/)
and [technical report](https://cdn.openai.com/pdf/67869394-cb91-4c12-888c-5cbd85c7814c/OpenAI-Hugging-Face%20Incident-Technical-Report.pdf).
Its relationships to NIST guidance are informative; this project does not claim
NIST conformance or government endorsement.

## Highlights

- **Thirteen deterministic controls** detect unauthorized cross-run side
  channels, channel-boundary violations, indirect egress, peer-authority
  laundering, cross-run credential use, evaluator access, unsafe persistence,
  missed response windows, delayed evidence preservation, unapproved restart,
  weak defense independence, and runtime control collapse.
- **Zero-content structural evidence** uses identifiers, offsets, bindings, and
  categorical outcomes only. Prompts, reasoning, message bodies, tool I/O,
  credentials, exploit payloads, and proprietary model data remain outside the
  protocol.
- **Accountable response evidence** binds decisions to their issuing actors and
  accepts escalation, containment, evidence-preservation, and restart events
  only from owner-declared response actors.
- **Independent defense analysis** distinguishes multiple controls from
  genuinely separate failure domains and reports when every declared defense
  for an objective has failed.
- **Recomputable outputs** include strict scenario/report JSON Schemas,
  content-addressed JSON, offline tamper verification, SARIF 2.1.0, response
  windows, communication paths, and the earliest violation visible in the
  supplied record.
- **Operational adoption surfaces** include three abstract non-operational
  profiles, an editable scenario, CI failure gates, ContinuousProof regression
  baselines, a community integration template, and stakeholder guidance for
  frontier labs, enterprises, security vendors, cloud providers, government
  agencies, and critical-infrastructure operators.
- **A responsive containment visual** explains the run boundary, shared-service
  channel, evaluator boundary, indirect egress, response clock, and zero-content
  evidence contract on the public dashboard.

## Install and run

```bash
pip install dspy-security-bench==0.19.0

dspy-security-bench collective describe
dspy-security-bench collective demo --out-dir artifacts/collectiveguard
dspy-security-bench collective run examples/collectiveguard-scenario.json \
  --json-out artifacts/collectiveguard/report.json \
  --sarif-out artifacts/collectiveguard/report.sarif.json \
  --fail-on-findings \
  --require-timely-containment
dspy-security-bench collective verify artifacts/collectiveguard/report.json
```

## Evidence boundary

CollectiveGuard analyzes the structural record supplied by an operator or
exporter. `no_violation_observed` means no rule violation appears in that
record; it does not prove telemetry completeness, model alignment, deployed
containment, production safety, or the absence of omitted activity.

Reports are technical assessment inputs—not certifications, compliance
determinations, government-authored requirements, procurement decisions, risk
acceptances, government endorsements, incident-response direction, or
authorizations to operate. System owners and accountable responders retain all
containment, notification, recovery, and deployment decisions.
